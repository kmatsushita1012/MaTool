# 案件別設計書

開発ガイドや検証手順とは分け、案件ごとの要件・設計判断・MVP 範囲・未確定事項を保存します。

## ディレクトリ命名

- 配置: `docs/projects/YYYYMMDD_snake_case/`
- 日付: 原則として案件の設計開始日。リリース予定日ではありません。
- 名前: 案件を識別しやすい短い英語の snake_case
- 主な設計書: 各案件ディレクトリの `spec.md`
- 詳細資料が増えたら同じディレクトリに追加し、`spec.md` からリンクします。

## 記載上のルール

- **確定済み仕様** と **実装の推奨案** を混同しない。
- 未確定事項を明示し、実装時に変更した判断は文書を更新する。
- 実装の正本はコード・API 定義。設計書には背景と判断理由を残す。
